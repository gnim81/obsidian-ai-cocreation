# obsidian-ai-cocreation

> Let AI move into your Obsidian vault, safely — a co-writing template with **enforced permission boundaries**, **explicit human-AI division of labor**, and **auditable iteration**.

## The problem

Connecting AI agents to a knowledge base for writing hits three walls:

1. **Afraid to grant write access** — one careless write can corrupt your raw sources, long-term notes, or finalized drafts;
2. **Re-explaining everything, every session** — context, audience, voice, taboos: gone the moment a session ends;
3. **No provenance** — which parts did the AI write? No way to audit after the fact.

This template answers with **enforced boundaries** (not prompt conventions), **context-as-asset**, and **baseline auditing**:

```
┌───────────────────────────────────────────────────────────────┐
│  L1  MCP vault-root pinning: project-rw can only write 03-Projects/ │
│  L2  .claude/settings.json deny: sources / finals / areas / governance │
│  L3  Vault Operator (optional): governs in-Obsidian AI plugins    │
│  L4  human_locked field lock: files you take over are propose-only  │
└───────────────────────────────────────────────────────────────┘
```

Every layer documents *who enforces it, on which path* — including the empirical finding that L3's shadow snapshots do **not** capture direct writes from external tools; on the external path, git (one commit per co-writing round) is the real safety net.

## Core design

**Three-layer content model** (where does a piece of content go):

| Layer | Location | What lives there | Who writes |
|---|---|---|---|
| Originals | `04-Resources/clippings/` | Third-party articles, stored verbatim | You (AI stages) |
| Judgments | `02-Areas/<area>/` | Your conclusions ("I" statements, valid in 2 years) | Human only (AI proposes) |
| Project sources | `03-Projects/<project>/10-source/` | Material for the current project | You only |

One line to remember: **Projects produce works, Clippings hold others' texts, Areas hold my judgments.**

**Project zones = physical permission boundary**: `10-source` read-only → `20-notes` writable → `30-drafts` writable (v1/v2 never overwritten + untouched copies in `_baseline/`) → `40-review` / `50-final` / `60-published` write-forbidden.

**Four human-AI operating modes**: script execution (pure mechanics) / AI direct-write (writable zones) / AI stages + human lands it (trust layer) / AI advises + human decides (destructive ops).

**Operations out of the box**: 14 slash commands in 5 functional groups + 3 deterministic bash scripts:

| Group | Commands |
|---|---|
| Intake `/intake/` | `collect` · `clip` · `triage` |
| Produce `/produce/` | `new` · `digest` · `draft` · `iterate` · `brief` · `archive` |
| Knowledge `/knowledge/` | `note` |
| Quality `/quality/` | `factcheck` · `voice` |
| Query `/query/` | `search` · `status` |

Scripts (`00-System/scripts/`) handle deterministic operations (mkdir / move / stats) — zero hallucination, zero tokens, runnable without an AI session. Also included: a status state machine (idea → … → archived), AI participation labels (`authored_by` / `ai_level`), 3 Bases boards, and writing templates.

## Quick start

```bash
git clone https://github.com/gnim81/obsidian-ai-cocreation.git my-vault
cd my-vault
bash init-vault.sh                 # optional: --areas "Writing,Coding,Investing"
```

Then: ① open `my-vault` in Obsidian (trust plugins, enable the core **Templates** plugin); ② launch your AI CLI (e.g. `claude`) at the vault root and approve the two MCP servers; ③ read the [Guide](GUIDE.md) and start your first project (or just run `/produce/new`).

- **Primary method: external AI CLI + MCP** (Claude Code / Codex CLI / Cursor). In-Obsidian AI plugins ([Claudian](https://github.com/YishenTu/claudian)) are optional enhancements — nothing breaks without them.
- Linux/macOS: overwrite `.mcp.json` with `.mcp.linux.json` (paths are generated by `init-vault.sh`).
- **No community plugins are required.**

## Layout

```
├── CLAUDE.md            AI constitution (permissions + hard rules + area routing; read first every session)
├── GUIDE.md             Human operating manual (9 chapters)
├── init-vault.sh        One-command init (MCP paths / custom areas / git init)
├── .claude/             Permission rules + 14 slash commands
├── .mcp.json            Dual MCP instances: vault-read (full, read-only) / project-rw (pinned to 03-Projects)
├── 00-System/           Templates, Bases boards, deterministic scripts
├── 01-Inbox/            Single entry point, cleared weekly (AI-writable)
├── 02-Areas/            Long-term areas: your judgments (AI read-only)
├── 03-Projects/         Co-creation zone (AI write-limited), with a demo project
├── 04-Resources/        clippings originals + voice reference (AI read-only)
└── 05-Archive/          Archived projects (AI read-only)
```
